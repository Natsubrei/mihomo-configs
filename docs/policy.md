# 分流策略与常见问题

三个入口共用 [`templates/policy.yaml`](../templates/policy.yaml)：30 个策略组、30 个 ACL4SSR 规则集、31 条分流规则。默认策略面向中国大陆日常使用，不代表适合所有网络。

## 默认如何选节点？

| 分组 | 默认行为 |
|---|---|
| 节点选择 | 使用「故障转移」，也可选自动测速、地区或原始节点 |
| 故障转移 | 每 60 秒检查，连续失败 2 次后强制体检；在健康候选中按顺序选择，不按速度排名 |
| 自动选择 | 按延迟选择，`tolerance: 100` 减少小幅波动造成的切换；未选中时也会测速 |
| 地区组 | 按节点名筛选，再测速；未选中时也会按 300 秒测速；空组使用 `REJECT` |
| OpenAI / 电报消息 / 油管视频 / 奈飞视频 | 跟随主选择，也可直接固定节点 |
| 微软云盘 / 微软服务 / 苹果服务 / 游戏平台 / 国内媒体 / 网易音乐 | 默认直连，可手动改为代理 |
| 谷歌FCM / 微软Bing | 默认代理，也可手动选择直连 |
| 规则更新 | 跟随主选择下载 GitHub 规则；原站可直连时可选 DIRECT |
| 漏网之鱼 | 未匹配其他规则的流量默认走代理 |

不覆写内核的 `GLOBAL`。全局模式不使用上述分流规则，手动选择 `DIRECT` 仍然会直连。

## 地区匹配与信息条目

支持香港、台湾、日本、新加坡、美国、韩国、德国的常见中文、英文、国家代码和旗帜，例如 `HK01`、`Hong Kong`、`🇭🇰`、`Taipei`、`JP01`、`Singapore2`、`USA02`、`Seoul`、`Frankfurt`。

这是**节点名称的启发式分类**，不是出口位置验证。特殊名称可能匹配多个地区或没有命中；未识别地区的节点仍在主选择和自动组中。需要自定义时，修改源模板的 `filter` 后重新构建。

`exclude-filter` 排除典型的流量/到期信息名称，不使用 `GB`、`Music`、倍率等宽泛词。信息条目可能只是正常节点的重复别名，排除是为了整理列表，不能据此认定它们导致断联。

## 为什么空组不直连？

内核的 `COMPATIBLE` 是直连兼容回退。为了避免空地区组静默直连，动态组明确使用 `empty-fallback: REJECT`。

这只覆盖**没有候选节点**的情况，不是系统级防泄漏开关，也不保证候选节点全部失效时还能找到可用链路。配置中的显式直连规则仍会直连。

## 规则下载与缓存

- 规则来自 [ACL4SSR/ACL4SSR](https://github.com/ACL4SSR/ACL4SSR)，公开配置只引用 URL，不复制第三方规则内容。
- `.list` 含 `DOMAIN-SUFFIX,...`、`IP-CIDR,...` 等前缀，统一使用 **`classical/text`**。包括 `ChinaDomain.list` 和 `ChinaCompanyIp.list`，不能按名字误改为 `domain` / `ipcidr`。
- 缓存位于 mihomo 工作目录的 `ruleset/generic/`，不是配置仓库。
- 下载默认通过「规则更新」组，需要可用节点或 GitHub 原站直连能力。首次下载无法凭模板解决所有网络依赖。
- 更新失败不意味着全部 `RULE-SET` 立即失效；内核可能继续使用有效缓存。请检查日志，不要反复删除缓存。
- 不强制 GEOIP/GEOSITE 数据文件，未被规则覆盖的国内地址也可能走代理。

## 连接仍然不稳定？

1. 先确认节点及网络可用。TCP 超时不足以认定某种特定封锁。
2. 健康检查成功只代表测试 URL 当时可用，不保证所有网站、地区解锁或长连接稳定。
3. 故障转移主要影响后续连接，不能无缝迁移已经断开的下载或 AI 流式响应。
4. AI、登录服务建议手动固定经过验证的节点，减少出口变化。
5. 检查应用是否真的经过代理；默认配置不会接管所有系统流量。
6. 不要通过关闭 TLS 校验、公开无认证管理接口来解决断联。

若凭据曾被公开，应向提供方重置，而不是只删除文件或帖子。
